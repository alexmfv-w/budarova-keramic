# PHOTO_PIPELINE.md — Подготовка фото: кто что делает

> Разделение труда: **пользователь** доводит художественное качество и отбирает кадры,
> **агент** делает всю техническую подготовку под веб скриптом на Этапе 6.

## Главный вывод

Апскейл до 5760×7680 для сайта **не нужен и вреден**: в вебе картинка всё равно ужимается
до 800–1600 px по длинной стороне. Замер на реальном файле проекта:

| Файл | Размер |
|---|---|
| `tripod2.png`, 5780×7680 | **62.5 МБ** |
| он же → WebP 1600 px (q78) | **104 КБ** |
| он же → WebP 800 px (q78) | **39 КБ** |

Это в **600 раз** меньше. Разницы на экране телефона не видно. Весь каталог из 74 фото
после конвертации займёт ~10–15 МБ вместо 2.8 ГБ — иначе GitHub Pages и мобильный интернет не потянут.

**Не масштабируй больше. Полезной остаётся только та часть обработки, что улучшает саму картинку:
шум, резкость, цвет, свет, фон.**

## Что делает пользователь (в порядке важности)

### 1. Отбор и выбраковка — даёт больше всего
74 файла на сайт не нужны. Ориентир: **3–5 кадров на изделие** (общий план, деталь фактуры,
вещь в интерьере/в руках, масштаб) + 10–15 кадров процесса и мастерской.
Дубли (`mhariom*` / `mharium*`, `proces_instruments` / `proceess_instuments`, `photo_N_0.png`) — убрать.
Лучше 30 сильных кадров, чем 74 средних: галерейный сайт ломается именно на слабых фото.

### 2. Единый цвет и свет — вторая по важности вещь
Сейчас кадры сняты в разном свете (белая кирпичная стена, стол, один кадр при свечах).
На сетке каталога это читается как «набор случайных фото», а не коллекция.
Решение: **один пресет на всю партию**. Lightroom (мобильный, бесплатный) — выставить один кадр,
скопировать настройки, применить ко всем: экспозиция, баланс белого, чуть приглушить насыщенность.
Земляная палитра сайта (глина, песок, охра) будет держаться, только если фото в неё попадают.

### 3. Кадрирование под сетку
Каталожные карточки — **вертикаль 4:5**. Кадрировать заранее, иначе браузер обрежет как попало
и половина изделий окажется без ножек. Для hero-кадров отдельно оставить 1–2 горизонтальных.

### 4. Чистка фона
Убрать бытовой мусор из кадра (ноутбук, ручка, розетки, край клеёнки). Для каталога — либо
однородный нейтральный фон, либо честный фон мастерской, но **последовательно один подход**.

### 5. Что отдать агенту
Готовые «мастер-копии»: **JPEG или PNG, 2000–3000 px по длинной стороне**, осмысленные имена
(`tripod-01.jpg`, `mharium-krasny-02.jpg`). Ресайзом, WebP и адаптивными версиями занимается скрипт — вручную не делать.

## Инструменты

| Задача | Чем | Комментарий |
|---|---|---|
| Цвет/свет партией | **Lightroom Mobile** (беспл.) | лучшее вложение времени: один пресет на все кадры |
| Отбор и кадрирование | Просмотр macOS / Lightroom | быстро, ничего специального не нужно |
| Удаление фона, тени | **Photoroom**, remove.bg, Canva | предметка одним нажатием, есть бесплатный лимит |
| Убрать лишний предмет | Photoshop Generative Fill; беспл. — **GIMP / Krita** (штамп) | точечно, не для всей партии |
| Расширить кадр / заменить фон | **Gemini (Nano Banana)**, Photoshop | см. ограничение ниже |
| Шум и резкость | Topaz Photo AI, Lightroom «Улучшить» | только если кадр реально шумный |
| Логотип | **Figma** | по договорённости делает пользователь |

**Жёсткое ограничение для любых ИИ-инструментов:** нейросеть может править **фон, свет, кадр** —
и не должна перерисовывать **само изделие**. Глазурь, роспись, сколы, фактура — это товар,
который человек получит по почте. Если ИИ «дорисовал» узор на триподе, покупатель получит другую вещь.
Правило: изделие — только фотография, всё вокруг — можно править.

## Что делает агент (Этап 6, автоматически)

Скрипт `tools/build-images.sh` на входе берёт мастер-копии, на выходе даёт:
- WebP в трёх ширинах — **480 / 960 / 1600 px**, качество 78;
- JPEG-фолбэк той же ширины для старых браузеров;
- готовые `<img srcset sizes loading="lazy" width height>` — без «прыжков» вёрстки при загрузке;
- имена файлов, совпадающие с ключами в JSON каталога.

Инструмент на машине уже есть: `cwebp` (`/opt/homebrew/bin/cwebp`) + системный `sips`. Ставить ничего не нужно.
