# ARCHITECTURE.md — Этап 5. Структура сайта

> Опора: `ANALYSIS_NOTES.md` (задача сайта), `DESIGN_NOTES.md` (вариант В2), `SITE_TEXTS.md` (тексты),
> `PHOTO_INVENTORY.md` (фото), `BEST_PRACTICES.md` (принципы).

## 1. Главная задача

Сайт — **витрина-каталог с историей**. Целевое действие каждой страницы одно:
**перейти к мастеру в Telegram, MAX или позвонить**. Корзины, оплаты и личного кабинета нет.

Отсюда следуют три правила, которым подчинена вся структура:
1. На любой странице способ связи доступен в один тап — без возврата на главную.
2. У каждой работы есть свой адрес, которым можно поделиться в переписке.
3. Раздел «Из последнего обжига» обновляется чаще всего, значит правка должна быть в одном файле данных.

## 2. Карта страниц

```
/                     Главная
/catalog/             Все работы + фильтры
/work/<slug>/         Карточка работы           ← адрес для отправки в переписке
/about/               О мастере
/stories/             Истории
/stories/<slug>/      Материал
/meetings/            Встречи
/contacts/            Контакты и FAQ
/404.html             Страница «не нашлось»
```

Восемь типов страниц, из них два — генерируемые (работы и истории).

### Главная — порядок блоков
Порядок закреплён прототипом `demo/c2-poyas.html` и утверждён:

| # | Блок | Задача |
|---|---|---|
| 1 | Шапка + пояс | навигация, сразу видно, что это керамика |
| 2 | Первый экран | «Керамика, которую делали до нас» + два действия |
| 3 | Полоса-манифест | цитата мастера; **разводит два фотоблока подряд** |
| 4 | Триподы | направление 1 |
| 5 | Мхариумы | направление 2 |
| 6 | Интерьер | направление 3 |
| 7 | Под заказ | индивидуальная работа + уаскос как пример |
| 8 | Из последнего обжига | 8 свежих работ, фильтры, ссылка в каталог |
| 9 | О мастере | доверие: лицо и цитата |
| 10 | Встречи | мастер-классы и церемонии |
| 11 | Контакты | связь + условия доставки |

Блок 3 не декоративный: без него фото героя и фото первой ленты сливаются на десктопе —
это ловилось на скриншотах и специально исправлено.

## 3. Навигация

**Пункты (5, укладывается в правило «не больше 5–7»):**
Работы · Истории · О мастере · Встречи · Контакты

- **Десктоп:** горизонтальное меню в шапке, шапка не липкая — страница короткая, липкая шапка съедает высоту.
- **Мобильная:** в шапке логотип и кнопка меню (48×48). Меню открывается панелью на весь экран,
  пункты списком с тап-зоной 56 px. Закрытие — крестик и клавиша Esc.
- **Подвал:** повтор навигации + контакты + «© Алёна Бударова, самозанятая».

**Мобильная кнопка связи.** Внизу экрана закреплена полоса «Написать мастеру» (Telegram / MAX / телефон).
Появляется после прокрутки первого экрана, прячется на странице контактов. Это главное действие сайта,
и заставлять человека искать его в подвале — терять заказ.

## 4. Компоненты

Переиспользуемые куски. Одинаковый вид в разных местах — один компонент, а не копия.

| Компонент | Где | Заметки |
|---|---|---|
| `belt` | между секциями | орнаментальный пояс, SVG в CSS-переменной, две толщины |
| `ribbon` | направления, «под заказ» | фото + текст, чередование сторон через `.flip` |
| `card` | каталог, «из обжига», похожие работы | фото 4:5, название, метка, цена/статус |
| `chips` | каталог, «из обжига» | фильтры, `aria-pressed`, работают без перезагрузки |
| `panel` | «о мастере», «встречи» | цветная плашка внахлёст на фото |
| `contact-list` | контакты, подвал | Telegram · MAX · телефон |
| `gallery` | карточка работы | 3–5 фото, свайп с `scroll-snap`, точки-индикаторы |
| `story-card` | истории | обложка + заголовок + лид |

**Правило цвета:** глиняная плашка `#A8452C` — блоки о человеке (мастер, манифест);
бирюзовая `#2E7C74` — события и действия (встречи). Не смешивать, иначе цвет перестаёт что-либо значить.

## 5. Карточка работы — самая важная страница

Это адрес, который мастер отправляет в переписке. Структура:

1. Галерея 3–5 фото: общий план → деталь фактуры → масштаб (в руках или рядом с предметом).
2. Название, категория, цена или «цена по запросу», статус наличия.
3. **Кнопка «Написать о работе»** — открывает Telegram; название работы подставляется в текст,
   чтобы мастеру не пришлось выяснять, о чём речь.
4. `story` — 2–4 предложения: что это и откуда взялось.
5. Характеристики — только заполненные поля. Пустые не выводятся: строка «Размеры: —» хуже, чем её отсутствие.
6. Для триподов и уаскос — блок про ритуал.
7. Доставка и оплата — коротко, со ссылкой на FAQ.
8. «Похожие работы» — 3–4 карточки той же категории.

Для проданного: статус «Продано», кнопка меняется на «Сделать похожую».

## 6. Данные

Один файл `data/catalog.json` — источник и для каталога, и для карточек.

```json
{
  "updated": "2026-09-02",
  "items": [
    {
      "slug": "tripod-zigzag",
      "title": "Трипод «Зигзаг»",
      "category": "tripod",
      "collection": null,
      "story": "Чаша на трёх ножках с треугольным орнаментом по охряному полю…",
      "ritual_usage": "Размер под порцию какао, из которой пили не спеша.",
      "materials": null,
      "dimensions": "200 мл",
      "care": null,
      "price": 1500,
      "availability": "in_stock",
      "featured": true,
      "images": ["tripod-zigzag-01", "tripod-zigzag-02"]
    }
  ]
}
```

- `category`: `tripod` · `mharium` · `interior` · `uasko`
- `availability`: `in_stock` · `on_order` · `sold`
- `price`: число или `null` → выводится «цена по запросу»
- `null` в `materials` / `dimensions` / `care` — поле просто не рендерится
- `images` — имена без расширения и размера; конкретные файлы подставляет шаблон
- `featured: true` — попадает в «Из последнего обжига» на главной

Отдельно `data/stories.json` для раздела «Истории» и `data/meetings.json` для «Встреч»
(пустой массив — блок показывает «даты объявляю в Telegram», и это нормальное состояние).

**Почему JSON, а не CSV:** нужны вложенные списки (`images`) и явный `null`. В CSV и то, и другое — костыль.

## 7. Сборка: нужна, и вот почему

`CLAUDE.md` разрешает сборку, «если станет явно нужно». Стало.

Работы будут отправлять ссылками в Telegram и MAX. Мессенджер показывает превью по OG-тегам,
которые читаются **из HTML до запуска JavaScript**. Если карточки рисуются скриптом на одной
странице `work.html?id=…`, все ссылки в переписке выглядят одинаково — одна картинка, один заголовок.
Для сайта, где переписка и есть канал продаж, это прямая потеря.

**Решение:** `tools/build.mjs` — скрипт на голом Node, без единой зависимости.
Читает `data/*.json` и шаблоны, раскладывает готовый HTML в `docs/`. Запуск — `node tools/build.mjs`.
Это не фреймворк и не сборщик: один файл, который можно прочитать целиком за пять минут.

**Что получаем:** у каждой работы свой адрес, свои OG-теги с её фотографией и ценой, нормальная
индексация, и при этом на выходе — обычная статика для GitHub Pages.

**Альтернатива, если сборку не хотим:** всё рисует JS, карточки живут по адресам вида
`/work.html?id=tripod-zigzag`. Работает, но превью в мессенджерах будет одинаковым у всех работ.
`[РЕШИТЬ: собираем скриптом или обходимся без него]` — рекомендую скрипт.

## 8. Файловая структура

```
/
├─ data/                 catalog.json · stories.json · meetings.json
├─ src/
│  ├─ templates/         page.html · work.html · story.html
│  ├─ css/               tokens.css · base.css · components.css · layout.css
│  └─ js/                filters.js · gallery.js · nav.js   (~150 строк всего)
├─ images/masters/       мастер-копии от мастера, 2000–3000 px
├─ tools/
│  ├─ build.mjs          JSON + шаблоны → docs/
│  └─ build-images.sh    мастер-копии → WebP 480/960/1600 + JPEG-фолбэк
├─ docs/                 ← публикуется на GitHub Pages
└─ *.md                  рабочие файлы проекта
```

`docs/` как корень публикации — GitHub Pages умеет это без Actions: в настройках репозитория
выбирается ветка `main` и папка `/docs`. Проще некуда: `git push` — и сайт обновлён.

## 9. Изображения

- Мастер-копии от мастера кладутся в `images/masters/`, имя = `<slug>-01.jpg`.
- `build-images.sh` делает WebP в трёх ширинах (480 / 960 / 1600, качество 78) и JPEG-фолбэк.
- В разметке — `srcset` + `sizes`, обязательные `width`/`height` (иначе вёрстка прыгает при загрузке).
- Первый экран: `fetchpriority="high"`, **без** `loading="lazy"`.
- Всё ниже первого экрана: `loading="lazy"`.
- Пропорции: карточка 4:5, лента 4:3, портрет мастера 4:5, первый экран 16:9.

Замер на реальном файле проекта: 62 МБ PNG → 104 КБ WebP при 1600 px. Подробности — `PHOTO_PIPELINE.md`.

## 10. Мобильная версия — отдельно

Проектируется первой, под 360–390 px, расширяется через `min-width`.

| Блок | Поведение на мобильной |
|---|---|
| Шапка | логотип + кнопка меню; меню — панель на весь экран |
| Первый экран | фото сверху, текстовая плашка внахлёст снизу |
| Ленты направлений | складываются в столбик: фото, под ним текст |
| Каталог | 2 колонки; фильтры переносятся на вторую строку |
| Галерея работы | горизонтальный свайп со `scroll-snap`, точки под кадрами |
| О мастере / Встречи | фото, под ним цветная плашка внахлёст |
| Связь | закреплённая полоса внизу экрана |

**Проверяется на каждом шаге:** тап-зоны ≥ 44–48 px, текст ≥ 16 px, горизонтального скролла нет,
ничего важного не спрятано в `hover`.

Как снимать: headless Chrome на macOS не открывает окно уже 500 px, поэтому мобильные кадры
снимаются через обёртку с `<iframe width=390>`. Секции глубже первого экрана — через обёртку
со сдвигом `iframe{position:absolute; top:-Npx}`, иначе ленивые фото не успевают загрузиться
и кадр выходит пустым. Записано в `DESIGN_NOTES.md`.

## 11. Доступность и производительность

- Семантические заголовки, один `<h1>` на страницу.
- Видимый фокус клавиатуры, уважение к `prefers-reduced-motion`.
- Осмысленные `alt` — описание работы, а не имя файла.
- Фильтры работают на кнопках с `aria-pressed`, а не на ссылках.
- Шрифты: Unbounded и Golos Text с Google Fonts, `display=swap`, только нужные начертания.
- Цель: главная < 500 КБ при первой загрузке, остальное — лениво.

## 12. Отступления от плана, сделанные при реализации

Записаны честно, чтобы файл не расходился с кодом.

1. **Шаблоны — не `.html`, а два модуля JS.** `tools/lib.mjs` (настройки, каркас, повторяющиеся блоки)
   и `tools/build.mjs` (страницы и запуск). Мини-движок для подстановок в HTML-файлы оказался бы
   сложнее самих шаблонов.
2. **JPEG-фолбэка нет.** WebP поддерживают все браузеры с 2020 года, а фолбэк весил 26 МБ против
   9.6 МБ у самих картинок. Убран целиком.
3. **Название работы не подставляется в Telegram.** Обещание из раздела 5 невыполнимо: ссылка ведёт
   в канал, а каналы не принимают предзаполненный текст. Вместо этого под кнопкой стоит подсказка
   с точным названием работы, которое нужно назвать в сообщении.
4. **Фильтры запоминаются в адресе** (`?c=tripod`). Это не планировалось, но иначе ссылка
   «Смотреть триподы» с главной вела бы в общий каталог без выбранного фильтра.
5. **Подпись на карточке — поле `meta`** («со мхом», «на три свечи»), а не название категории.
   Дублировать категорию под заголовком оказалось бессмысленно.

## 12а. Что изменилось в цикле правок 03.09.2026

Не переписываю разделы выше — фиксирую то, что поменяло сам принцип.

1. **У карточки появились поля `meta`, `food_note`, `coming`.** `food_note: true` включает дисклеймер
   про глазурь — он показывается только у посудных форм (триподы, уаскос, блюда, тарелки), а не у всех
   работ подряд. `coming: true` с пустым `images` рисует честную заглушку «фото скоро» вместо картинки:
   позицию можно завести до съёмки.
2. **`story` стало необязательным.** Пустое описание не выводится — так убраны сочинённые тексты
   там, где заказчик их не подтвердил.
3. **История — не плоский массив абзацев.** Блок может быть строкой (абзац), `{h}` (подзаголовок),
   `{callout}` (выделенная мысль на глиняном фоне) или `{cards}` (нумерованные карточки).
   Понадобилось для материала «5 причин завести мхариум»: сплошной колонкой он не читался.
4. **Блок «Под заказ» с главной убран** по решению заказчика. Раздел «Уаскос» остался только
   фильтром в каталоге.

## 13. Что решить до Этапа 6

1. **Сборка скриптом или без неё** (раздел 7). Рекомендую со скриптом — из-за превью в мессенджерах.
2. **Адрес сайта:** `budarova.github.io/keramika` или свой домен позже.
3. **Названия работ** — из `SITE_TEXTS.md`, пока рабочие.
4. **Нужен ли блок с реквизитами и офертой** — самозанятость на сайте указывать или нет.
