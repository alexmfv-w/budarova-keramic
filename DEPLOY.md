# DEPLOY.md — Этап 7. Публикация на GitHub Pages

> Статус: **всё готово к публикации, но сайт ещё не опубликован.**
> Публикация делает работы, фотографии и телефон видимыми всему интернету,
> поэтому последний шаг — за владельцем.

## Что уже сделано

- `docs/` собрана и проверена локально: 29 страниц, битых ссылок нет.
- В `docs/` лежит `.nojekyll` — иначе GitHub Pages выкинет всё, что начинается с подчёркивания.
- Пути к файлам выводятся из имени репозитория (константа `REPO` в `tools/lib.mjs`).
- `robots.txt` и `sitemap.xml` сгенерированы.

## Первая публикация

Репозиторий называется **`budarova-keramic`** — от его имени зависит адрес сайта.

```bash
cd /Users/alex/work/art_cheramic_store
git init
git add .
git commit -m "Сайт-магазин керамики Бударовой"
git branch -M main
git remote add origin https://github.com/alexmfv-w/budarova-keramic.git
git push -u origin main
```

Дальше в интерфейсе GitHub: **Settings → Pages**
- Source: `Deploy from a branch`
- Branch: `main`, папка: **`/docs`**
- Save

Через минуту-две сайт открывается по адресу **`https://alexmfv-w.github.io/budarova-keramic/`**.

Аккаунт `alexmfv-w` уже прописан в `tools/lib.mjs` (`SITE.origin`), пересобирать ничего не нужно.
Если аккаунт поменяется — поправьте эту константу и запустите `node tools/build.mjs`,
иначе ссылки в превью для мессенджеров будут вести не туда.

**Репозиторий должен быть публичным.** На бесплатном тарифе GitHub Pages из приватного
репозитория не публикуется.

**`old_useful_materials/` в репозиторий не попадёт** — так прописано в `.gitignore`.
Там 2.8 ГБ исходников, GitHub их не примет. Держите эту папку в отдельной резервной копии:
это первоисточник, из которого собраны все мастер-копии.

## Обновление сайта

```bash
node tools/build.mjs      # пересобрать страницы
python3 tools/verify.py   # сверить собранное с правками: тексты, цены, ссылки, картинки
git add -A
git commit -m "что изменилось"
git push
```

Через минуту изменения на сайте. Больше ничего делать не нужно.

### Про `git add -A` — это не придирка

Именно `-A`, а не `git add -u` и не перечисление файлов руками. Новая работа — это новая
папка `docs/work/<слаг>/` и новые файлы в `docs/img/`; `git add -u` их не увидит, потому что
он берёт только уже отслеживаемые файлы. Так уже случилось 3 сентября: в коммит попали
`catalog/index.html` и картинки, а сами страницы работ — нет. Ссылки в каталоге вели
на 404, хотя локально всё открывалось.

Проверить перед пушем, что ничего не забыто:

```bash
git status --porcelain | grep '^??'   # должно быть пусто
```

## Как добавить новую работу

1. Положите фотографии в `images/masters/` под именами `<слаг>-01.jpg`, `<слаг>-02.jpg`.
   Размер — 2000–3000 px по длинной стороне (см. `PHOTO_PIPELINE.md`).
2. `bash tools/build-images.sh` — сделает WebP в трёх размерах.
3. Добавьте объект в `data/catalog.json`. Обязательны `slug`, `title`, `category`, `story`,
   `availability`, `images`. Незаполненные `materials`, `dimensions`, `care` оставьте `null` —
   они просто не покажутся.
4. `node tools/build.mjs`, затем `git add -A && git commit && git push`.

`featured: true` выводит работу в блок «Из последнего обжига» на главной.
Продалась — поменяйте `availability` на `"sold"`: цена сменится на «Продано»,
а кнопка — на «Сделать похожую».

## Как добавить событие во «Встречи»

В `data/meetings.json`, в массив `items`:

{ "title": "Мастер-класс по росписи", "date": "12 октября, 15:00",
  "place": "студия «Кисть и Перо»", "note": "Запись в Telegram" }

это нормальное состояние, а не поломка.

## Проверка перед публикацией

Локальный просмотр (адреса вида `/budarova-keramic/...` требуют этой подпапки):

```bash
mkdir -p /tmp/preview && ln -sfn "$PWD/docs" /tmp/preview/budarova-keramic
cd /tmp/preview && python3 -m http.server 8747
# открыть http://localhost:8747/budarova-keramic/
```

Обязательно посмотреть **на настоящем телефоне**, а не только в браузере на компьютере.

## Свой домен

### Что означает ошибка «InvalidDNSError»

> `budarova.keramic.com is improperly configured. Domain's DNS record could not be retrieved.`

GitHub спросил у мировой системы DNS, куда ведёт это имя, и не получил ответа, указывающего
на GitHub. Вписать домен в настройках недостаточно: **GitHub не управляет вашим доменом**.
Записи создаются там, где домен куплен, — у регистратора.

Отсюда главное условие: **домен должен быть ваш**. Нельзя занять поддомен чужого домена:
если `keramic.com` принадлежит кому-то другому, доступа к его DNS у вас нет, и подключить
`budarova.keramic.com` не получится никак.

### Порядок действий, если домен свой

1. **Купить домен**, если его ещё нет. Для России — reg.ru, timeweb, beget; зона `.ru`
   стоит примерно 200–1000 ₽ в год.
2. **Создать DNS-записи** в панели регистратора.

   **Поддомен** (`www.example.ru`, `shop.example.ru`) — одна запись CNAME:

   | Тип | Имя | Значение |
   |---|---|---|
   | CNAME | `www` | `alexmfv-w.github.io.` |

   **Корень домена** (`example.ru` без префикса) — CNAME там запрещён, нужны четыре A-записи:

   | Тип | Имя | Значение |
   |---|---|---|
   | A | `@` | `185.199.108.153` |
   | A | `@` | `185.199.109.153` |
   | A | `@` | `185.199.110.153` |
   | A | `@` | `185.199.111.153` |

   Для IPv6 дополнительно четыре AAAA: `2606:50c0:8000::153`, `8001::153`, `8002::153`, `8003::153`.

3. **Подождать.** Записи расходятся по миру от нескольких минут до суток. Пока не разошлись,
   GitHub будет показывать ту же ошибку — это нормально, не признак поломки.
4. **Вписать домен** в Settings → Pages → Custom domain и нажать Save.
5. **Включить Enforce HTTPS** — галочка появится через несколько минут после проверки домена.

### Если переименовать репозиторий

Адрес сайта = `<логин>.github.io/<имя репозитория>/`. Переименовали репозиторий — поменяйте
константу `REPO` в `tools/lib.mjs` и пересоберите. Иначе страница откроется голым текстом
без стилей и фотографий: все пути будут вести на старое имя.

### Обязательный шаг со стороны сайта

Со своим доменом сайт живёт **в корне**, а не в подпапке `/budarova-keramic`. Если этого не учесть,
все ссылки на стили, скрипты и фотографии сломаются — страница откроется голым текстом.

В `tools/lib.mjs` сверху есть одна строка:

```js
const DOMAIN = null;              // подпапка: alexmfv-w.github.io/budarova-keramic/
const DOMAIN = 'example.ru';      // сайт в корне своего домена
```

Впишите домен, запустите `node tools/build.mjs` — сборка сама поменяет все пути,
адреса в превью для мессенджеров и положит `docs/CNAME`. Проверено в обе стороны.

Если файл `docs/CNAME` есть, а `DOMAIN` остался `null`, сборка предупредит об этом
в консоли и CNAME не тронет.

### Если домена пока нет

Ничего страшного: `https://alexmfv-w.github.io/budarova-keramic/` — полноценный рабочий адрес,
бесплатный и с HTTPS. Домен можно подключить в любой момент, сайт при этом не переделывается.
